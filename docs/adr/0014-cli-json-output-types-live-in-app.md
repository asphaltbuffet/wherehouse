# CLI JSON output shapes are app-owned projection types, not tags on the shared result types

Each command's `--json` output shape is a dedicated type in `internal/app/output.go` (`ListItem`, `ScryItem`, `MoveOutput`, `StatusOutput`, `AddOutput`, `HistoryItem`, …), built from the rich `app.*Result` types by a pure projector function (e.g. `ToListItems([]EntityResult) []ListItem`). Commands call the projector and hand the result to `cli.OutputWriter.Render(v, textFn)`; they no longer declare local `xxxResult`/`xxxEntry` structs, call `.String()` on enums, or branch on `--json` themselves. The projector and the JSON tags live in `app`; the text formatter (which may use `internal/styles`) stays at the `cmd`/`cli` boundary.

We rejected the originally-proposed alternative (issue #209): putting JSON tags directly on the existing `app.EntityResult`/`FindResult`/`HistoryResult` and marshalling them whole. That proposal assumed every command's JSON shape is a 1:1 of one shared result type. It is not. `EntityResult` is the rich, typed, eight-field currency the `internal/web` layer consumes field-by-field (`entity.Status`, `entity.EntityType`, breadcrumbs, icons); the CLI wants a narrow, stringified, four-field projection. Tagging the shared type would either leak presentation tags onto the web layer's domain view or force every CLI consumer to the same shape — and `omitempty` cannot express *caller-conditional* field selection (it keys on the value, not the caller; it would also silently drop a meaningful `has_children: false`). Distinct per-command output types keep the two consumers decoupled and keep each command free to evolve its own shape.

Enum serialization is solved at the domain layer, not per command: `inventory.EntityType`, `EntityStatus`, and `EventType` implement `MarshalJSON`/`UnmarshalJSON`, emitting their string names (matching the DB's `TEXT`/`CHECK` storage) and erroring on an out-of-range value. A zero-valued enum cannot arise from real data (the schema stores status as `TEXT NOT NULL DEFAULT 'ok'`), so the error path is a construction-bug guard, not a data case.

As part of this change, `move --json` stops emitting `old_path` (and the text output stops showing the source). Where an item *was* is recorded by the move event and surfaced through `history`; the move result is a projection of current state only. This collapses the one command whose output was assembled from data straddling the `cmd`/`app` boundary (the old path lived only in the command's pre-call scope) into a clean projection of the `EntityResult` that `ReparentEntity` already returns. This is a deliberate breaking change to the `move` JSON contract.

This extends ADR 0013 (logic out of `cmd/`) to the output seam and generalizes the per-command-shape precedent set by ADR 0011 (doctor JSON output shape). It does not change `cli.OutputWriter.Render`'s responsibility, which remains only the `--json`-vs-text branch; `Render` does not run projectors and is not generic over a projector function.
